# 巨大な会話で遅くなる場合

2026-10-26、Issue #116。これは会話の破棄やルーター再起動を前提にしない改善です。

## 確認できた原因と修正

要約する履歴を予算内へ分割する処理は、項目を追加するたびに全prefixを計測していました。
数千件の履歴では同じ本文を何千回もJSON化するため、ローカルCPU時間が二次的に増えます。
修正版は候補を倍々に伸ばし、上限を超えた区間だけ二分探索します。使うモデル、要約要求の内容、
履歴の順序・境界、画像・暗号化itemの扱い、サロゲートペアを保持する分割は変えません。

```sh
node --test test/summary-chunk.test.mjs
node scripts/benchmark-summary-chunk.mjs
```

合成履歴だけを使い、APIや認証情報へ接続しません。実測値はローカルの分割処理に限定されます。
上流の推論待ち、ネットワーク、モデル切替の要約生成時間まで同じ割合で改善するとは限りません。

同日の合成データ実測（4096件中3000件、約1.6MB）:

| 指標 | 修正前 | 修正後 |
|---|---:|---:|
| 全prefixの計測回数 | 3001 | 24 |
| 累積計測bytes | 2,402,579,920 | 21,645,203 |
| ローカル経過時間 | 4425.42ms | 36.41ms |

CPU競合や端末によって時間は変動します。選ばれた3000件と残り1096件は両版で完全一致を確認しています。

## 会話の成長を早めに圧縮する

```sh
python3 scripts/latency_config.py          # 設定案だけ確認
python3 scripts/latency_config.py --apply  # バックアップ後に保存
```

未指定のキーだけに以下を設定します。既存の明示値は0も含めて維持します。

```toml
model_auto_compact_token_limit = 128000
model_auto_compact_token_limit_scope = "body_after_prefix"
```

`body_after_prefix`は持ち越したprefixの後の増加分で判定します。大きな固定指示やツール定義だけで
低い閾値に毎回到達する設定を避けます。ただしモデル全体のコンテキスト制約は別途適用されます。
この閾値は運用上の選択値で、速度の保証値ではありません。圧縮には追加のモデル処理が発生し、
要約による情報の省略もあり得ます。必要な判断や成果物はIssueとファイルへ残してください。

モデル、provider、接続先、認証、MCP、カタログ、保存会話は変更しません。
設定は新しく起動するCodexから確認してください。開いた画面への即時反映は保証しません。
戻す場合は表示されたバックアップと現在の設定を比較し、この2キーだけを元へ戻してください。
その後の独立した設定変更をバックアップ全体で上書きしないでください。

## 退役した8790へ接続する画面

稼働中のCodexが保持する接続設定と、新規起動時の設定は異なることがあります。
8790は退役し、正規ポートは8791だけになりました。8790に向く画面は通信できません。
保存会話を削除する必要はありません。
新規起動時の実効provider/base URLを確認し、既存会話の再開は接続先を明示して別途検証します。
すべての`resume`が常に作成当時のURLを保持するとは今回の調査では確認していません。

## 根拠

- [Issue #116](https://github.com/nanameru/codex-bridge/issues/116)
- 実装: `src/compaction-handoff.mjs` の `takeSummaryChunk` と呼び出し元のtoken/byte判定。
- 過去の稼働ログ: `~/.codex/log/model-router.log`。GPTの例は推定478321 tokens、headers 20402ms。
  OpenCodeの例ではツール定義が1457146 bytes。これは推定値と個別要求の記録で、全体の平均ではありません。
- [OpenAI設定リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference): 閾値とscopeの定義。
- ユーザー提供の経緯はPKB `document:codexbridge-latency-report-2026-10-26` revision 1。
  報告されたCPU 40〜60%やゾンビプロセスは当時の計測を再現していないため未検証です。
