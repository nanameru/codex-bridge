# 圧縮・引き継ぎモデル（Issue #126）

Bridgeの既定要約モデルは `gpt-6-luna`。DeepSeek等のremote compaction v2、GPT会話のremote compaction（v2/旧compact endpoint）、圧縮履歴を文章へ変換する引き継ぎと入力上限対策の要約で共用する。通常の会話モデルと選択状態は変えない。明示した独立Responses直接接続はこの方針の対象外。

Lunaがカタログにない場合は圧縮・引き継ぎをエラーで停止する。高価なSolへの自動退避はしない。ChatGPT認証のまま利用し、APIキーの追加や購入をしない。既存の暗号化履歴を単純な文字列変換で復号する処理はない。

公式Standardクレジット料金ではGPT-6 Lunaの入力/出力は2.5/12.5 credits/1M tokens、GPT-6.1 Solは50/250。キャッシュ入力は0.25/2.5。含有サブスク枠の消費率や要約全体の削減率はこの単価比だけでは保証できない。
出典: https://learn.chatgpt.com/docs/pricing （2026-10-27確認）。

既存の起動済みチャットも、同じ共通routerを使う限りサーバー更新後の次の圧縮から適用される。進行中の要求は途中でモデルを変更しない。routerを迂回する独立接続には適用しない。会話DBや選択モデルの書換えは不要。

healthの `summary_model` で稼働設定を確認できる。既存の要約キャッシュはモデルもキーに含む。モデル変更後に以前のSol要約をLunaの結果として誤用しない。分割予算・予約出力・指示と未完了ツールの保護は従来どおり。

## 検証

Node348件・Python138件成功。実Codex 0.164.0と模擬上流で、GPT/DeepSeek圧縮・Luna引き継ぎ・DeepSeek復帰・resume・認証分離を確認。実TUIのWorking復帰も成功。

既存ChatGPT認証で合成履歴を用いたLuna実接続は圧縮200→引き継ぎ200、期限・禁止事項・次工程・識別語の保持を確認。成功2要求は入力180/出力89=計267 tokens。最初の上限2048指定は400で拒否され、compaction_triggerはmax_output_tokens指定時に最低20000を要求することを確認した。予約数と実出力は異なる。この試験は元のユーザー会話を送らず、Lunaの合成圧縮結果だけを次のLuna要求へ渡した。既存Sol暗号化履歴を含む全会話の要約品質を実APIで保証するものではない。
