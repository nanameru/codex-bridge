# Codex への導入依頼

まず `START_HERE.md` を読んでください。これは配布物を受け取った利用者を支援するための指示です。

1. preflight を実行し、OS、依存、Codex 導入形式、`CODEX_HOME`、既存ファイルとポートの状態を確認する。設定・認証・会話の本文や鍵の値は表示しない。
2. 利用者に提供元、モデル、保存先、ポートを尋ねる。OpenCode Go の単体 Bridge、統合ルーター、または通常の OpenAI 接続を選べる。統合版は本人が所有するカタログ、初期モデル、OpenAI 要約モデル、ポートを選ぶ。既存設定・サービスは変更も停止もしない。
3. OpenCode Go または統合ルーターの場合は `preview` を実行し、起動するプロセス、今回だけの CLI オプション、各提供元と要約による追加の外部送信、保存先、費用の可能性を秘密値なしで説明する。設定を編集する別経路ならバックアップ、変更範囲、復元方法を示す。
4. 明示承認まで起動・導入・設定変更をしない。承認されたら `run` を利用者自身の端末で実行し、`YES` の確認と API キーの非表示入力は利用者自身に任せる。鍵をチャットへ求めない。自動インストール、課金を伴う推論や外部送信を勝手にしない。
5. 前景 Bridge／router の local health と Codex 起動状態を区別して報告する。実推論は本人が明示的に選んだ場合だけ行う。未確認の OS や機能は未確認と伝える。

不安全なリンク、ファイル、権限、利用中ポート、既存 `bridge-portable` 設定、未対応認証を発見したら停止し、迂回・上書きしない。Windows ネイティブは ACL 検証がないため起動せず WSL の案内に従う。
