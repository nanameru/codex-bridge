# 圧縮要約失敗の入力・分類修正（Issue #171）

## 観測と確定範囲

remote compactで要約先からHTTP200内のerrorイベントを受け、Bridgeがunknown_error・試行1回として502を返した。元ログは保持されている。元エラー本文は記録されておらず、実要求の再送は成功したため、この障害の上流側の拒否理由までは特定できない。

コードで次の不備を確認した。

- 要約用要求のtoolsは空だが、入力が予算内なら過去のツール呼び出しを構造化itemのまま送っていた。分割要約では既に履歴データへ変換しており、入力長によって扱いが異なっていた。
- エラー抽出がcodeだけを参照していた。typeだけ、またはcodeがnullの応答はunknown_errorに落ち、一時障害でも再試行されなかった。

## 修正

直接・分割の両方で既存transcriptFragmentsを使い、過去の呼び出しを要約対象データとして送る。画像と暗号化checkpointは保持する。元ログ・現在の指示・最新要求は編集しない。

JSON、HTTP拒否、SSE error/response.failedで、許可済みcodeを優先し、なければ許可済みtypeから分類する。本文や任意のコードは診断へ転記しない。一時障害は既存の最大2試行、不正要求や不明分類は再試行しない。完全な要約だけをキャッシュ・公開する。

## 検証

- 新規2テストは修正前で両方失敗、修正後で成功。
- 要約・chunk・checkpoint・budget関連49件成功。
- 対応PythonをPATHに指定した全Nodeテスト410件成功。初回は端末既定Pythonがtomllib非対応で、認証テスト8件が失敗した。
- デスクトップ画面遷移E2Eと元障害の同一条件での実上流再現は未実施。元上流原因を推測で確定扱いにしない。
